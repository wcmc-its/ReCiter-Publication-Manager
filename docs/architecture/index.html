ReCiter Publication Manager — Architecture

The web UI of the ReCiter suite: librarians, faculty, and departmental staff use it to curate which publications belong to each scholar and to generate bibliometric reports. A Next.js app that proxies the ReCiter disambiguation engine and reads the ReCiterDB MySQL reporting store, deployed as a container on Amazon EKS behind SAML single sign-on.

View 1 · system context

System context — what feeds it, who it serves

People sign in through a SAML identity provider and use Publication Manager to curate publications and build reports. The app proxies the ReCiter engine and PubMed Retrieval Tool for disambiguation/search, reads and writes the ReCiterDB MySQL store via Sequelize, and reaches out to SMTP, a headshot API, and usage tracking.

View 2 · container internals (C4)

Inside the Next.js container

One container, five layers. The browser (React pages + Redux) hits Next.js. middleware.ts decodes the next-auth JWT and gates page routes. API routes under pages/api delegate to controllers that either proxy the ReCiter/PubMed REST APIs or query ReCiterDB through the Sequelize data layer. Reports are built in-process with exceljs and handlebars.

View 3 · request & data flows

Three core journeys

① Sign-in: the IdP posts a SAML response to saml-acs, which auto-submits to the next-auth callback; saml2-js verifies it, the user is matched in admin_users, and a JWT session is issued. ② Curate: the curate page calls the ReCiter feature-generator (by/uid, score≥30), pending feedback is merged, and publications land in Suggested / Accepted / Rejected; accept/reject writes back to ReCiter goldstandard. ③ Report: reports read the nightly analysis_* tables via Sequelize and render CSV / RTF / bibliometric files.

View 4 · deployment & CI/CD

From git push to running pods on EKS

A push to a master or *dev branch drives CodePipeline (Source → ManualApproval → Build). CodeBuild pulls SAML certs from S3 and Docker creds from Secrets Manager, builds the multi-stage node:22-alpine image, pushes it to ECR, then kubectl set image rolls it onto the reciter-pm-prod / reciter-pm-dev Deployment. Traffic enters via an ALB Ingress → Service → Pod (:3000); the pod reads ReCiterDB and calls the ReCiter / PubMed APIs.

View 5 · access control

Roles → permissions → gated routes

At sign-in, a user's roles (and curation scope) are read from admin_users_roles, turned into capabilities by getCapabilities() / the data-driven permission tables, and embedded in the next-auth JWT. On every gated navigation, middleware.ts decodes that token and checks the route's required permission via ROUTE_PERMISSIONS, redirecting to the user's landing page when it's missing. /authorships is the exception — gated directly by role (Superuser or Curator_All), not by a permission flag.
